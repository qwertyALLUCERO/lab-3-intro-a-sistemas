\section{Resumen}
Este laboratorio implementó un sistema de comunicación entre procesos (IPC) utilizando colas de mensajes POSIX en Linux. Se desarrollaron programas productores (\texttt{send.c}) y consumidores (\texttt{receive.c}) que intercambian información mediante las primitivas \texttt{msgget}, \texttt{msgsnd}, \texttt{msgrcv} y \texttt{msgctl}. Se realizaron experimentos para analizar situaciones críticas: acumulación de mensajes cuando el consumidor es lento, y buffer vacío cuando el consumidor es rápido. Los resultados confirmaron el comportamiento FIFO de las colas de mensajes, la correcta sincronización entre procesos y se logró transmitir exitosamente más de 100 mensajes con retardos aleatorios, demostrando robustez en diferentes condiciones de carga. Adicionalmente, se probaron escenarios de múltiples productores simultáneos y se respondieron las preguntas sobre orden de recepción y estrategias de broadcast.

\section{Introducción y Objetivos}

\subsection{Introducción}
En sistemas operativos modernos, la comunicación entre procesos (Inter-Process Communication, IPC) es fundamental para permitir que múltiples tareas cooperen y compartan información. Las colas de mensajes son una de las técnicas clásicas de IPC en sistemas Unix/Linux, proporcionando un mecanismo de comunicación asíncrona basado en el paso de mensajes estructurados.

A diferencia de otros métodos como pipes o memoria compartida, las colas de mensajes ofrecen:
\begin{itemize}
  \item \textbf{Persistencia}: Los mensajes permanecen en la cola hasta ser leídos
  \item \textbf{Tipificación}: Mensajes con diferentes tipos para filtrado selectivo
  \item \textbf{Atomicidad}: Operaciones de envío/recepción atómicas garantizadas por el kernel
  \item \textbf{Buffering}: Cola administrada por el sistema operativo
\end{itemize}

Este laboratorio explora estos conceptos mediante implementaciones prácticas del problema productor-consumidor, un patrón fundamental en programación concurrente.

\subsection{Objetivos}
\begin{itemize}
  \item Implementar comunicación entre procesos usando colas de mensajes POSIX
  \item Utilizar las primitivas \texttt{msgget}, \texttt{msgsnd}, \texttt{msgrcv} y \texttt{msgctl}
  \item Generar y transmitir 100+ mensajes alfanuméricos con retardos aleatorios de producción
  \item Analizar el comportamiento del sistema cuando:
  \begin{itemize}
    \item A) Hay más mensajes que capacidad de procesamiento (buffer lleno)
    \item B) El consumidor procesa más rápido que el productor (buffer vacío)
  \end{itemize}
  \item Resolver cómo enviar mensajes a múltiples consumidores (broadcast)
  \item Determinar el orden de recepción con múltiples productores simultáneos
  \item Justificar las respuestas mediante experimentación práctica
\end{itemize}

\section{Marco Teórico}

\subsection{Colas de Mensajes en Linux}
Las colas de mensajes son estructuras de datos mantenidas por el kernel que permiten a procesos intercambiar información en forma de mensajes. Cada mensaje tiene una estructura definida por el usuario que debe comenzar con un campo de tipo:

\begin{lstlisting}[language=C, caption=Estructura básica de un mensaje]
struct mensaje_t {
    long tipo;              // Tipo de mensaje (obligatorio)
    // ... campos de datos definidos por el usuario
};
\end{lstlisting}

\textbf{Características clave:}
\begin{itemize}
  \item Identificadas por una clave numérica (\texttt{key\_t})
  \item Operan en modo FIFO (First-In-First-Out) por tipo de mensaje
  \item Tienen límites de tamaño configurables en el sistema
  \item Persisten hasta ser eliminadas explícitamente con \texttt{msgctl()}
\end{itemize}

\subsection{Primitivas IPC}

\subsubsection{\texttt{msgget(key, flags)}}
Crea una nueva cola de mensajes o conecta a una existente.
\begin{lstlisting}[language=C]
int msqid = msgget(CLAVE_COLA, IPC_CREAT | 0666);
\end{lstlisting}
Retorna el identificador de la cola (\texttt{msqid}) o -1 en caso de error.

\subsubsection{\texttt{msgsnd(msqid, msg, size, flags)}}
Envía un mensaje a la cola especificada.
\begin{lstlisting}[language=C]
msgsnd(msqid, &msg, sizeof(msg) - sizeof(long), 0);
\end{lstlisting}
El tamaño debe excluir el campo \texttt{tipo}.

\subsubsection{\texttt{msgrcv(msqid, msg, size, type, flags)}}
Recibe un mensaje de la cola. El parámetro \texttt{type} determina el comportamiento:
\begin{itemize}
  \item \texttt{type = 0}: Recibe el primer mensaje disponible (cualquier tipo)
  \item \texttt{type > 0}: Recibe primer mensaje del tipo especificado
  \item \texttt{type < 0}: Recibe mensaje con tipo menor o igual a $|type|$
\end{itemize}

\begin{lstlisting}[language=C]
msgrcv(msqid, &msg, sizeof(msg) - sizeof(long), 0, 0);
\end{lstlisting}

\subsubsection{\texttt{msgctl(msqid, cmd, buf)}}
Controla y obtiene información de la cola.
\begin{lstlisting}[language=C]
msgctl(msqid, IPC_RMID, NULL);  // Eliminar cola
msgctl(msqid, IPC_STAT, &buf);  // Obtener estadisticas
\end{lstlisting}

\subsection{Problema Productor-Consumidor}
\textbf{Productor:} Genera datos y los envía a la cola mediante \texttt{msgsnd()}. \\
\textbf{Consumidor:} Recibe datos de la cola con \texttt{msgrcv()} y los procesa.

\textbf{Desafíos:}
\begin{itemize}
  \item Sincronización: ¿Qué ocurre si el productor es más rápido que el consumidor?
  \item Acumulación: ¿Cuántos mensajes puede almacenar el buffer?
  \item Orden: ¿Se mantiene el orden de envío cuando hay múltiples productores?
\end{itemize}

\subsection{Limitaciones del Sistema}
Linux impone límites configurables (visibles con \texttt{ipcs -l}):
\begin{itemize}
  \item \texttt{msg\_qbytes}: Tamaño máximo de la cola en bytes
  \item \texttt{msgmni}: Número máximo de colas en el sistema
  \item \texttt{msgmax}: Tamaño máximo de un mensaje individual
  \item \texttt{msgmnb}: Número máximo de bytes por cola
\end{itemize}

\subsection{Diseño de la Estructura de Mensajes}
\begin{lstlisting}[caption=Estructura completa del mensaje implementado]
struct mensaje_t {
    long tipo;                // Tipo de mensaje (TIPO_DATO o TIPO_FIN)
    int id_send;              // ID del productor (1, 2, 3, ...)
    int numero_secuencia;     // Número de secuencia (1, 2, 3, ...)
    int dato;                 // Dato numérico aleatorio (0-999)
    char texto[128];          // Mensaje alfanumerico
    time_t timestamp;         // Marca de tiempo de creacion
};
\end{lstlisting}

\textbf{Justificación del diseño:}
\begin{itemize}
  \item \texttt{tipo}: Permite filtrado en \texttt{msgrcv()} y diferencia datos de señales FIN
  \item \texttt{id\_send}: Identifica el origen en escenarios multi-productor
  \item \texttt{numero\_secuencia}: Verifica integridad y detecta pérdida de mensajes
  \item \texttt{dato}: Valor numérico para análisis estadístico
  \item \texttt{texto}: Cumple requisito de mensaje alfanumérico del laboratorio
  \item \texttt{timestamp}: Permite análisis de tiempos de espera y latencia
\end{itemize}

\subsection{Implementación del Productor (send.c)}

\textbf{Características principales:}
\begin{itemize}
  \item Genera 100 mensajes por defecto (configurable por argumento)
  \item Retardo aleatorio de 50-500 ms entre mensajes (requisito del laboratorio)
  \item Texto alfanumérico con letra aleatoria incluida
  \item Mensaje FIN al terminar para señalizar finalización
  \item Identificador único por productor (\texttt{id\_send})
\end{itemize}

\textbf{Pseudocódigo:}
\begin{enumerate}
  \item Parsear argumentos: \texttt{id\_send} y cantidad de mensajes
  \item Conectar/crear cola de mensajes con \texttt{msgget()}
  \item Para \texttt{i = 1} hasta \texttt{total\_messages}:
  \begin{enumerate}
    \item Generar retardo aleatorio (50-500 ms)
    \item Preparar mensaje con:
    \begin{itemize}
      \item \texttt{tipo = TIPO\_DATO}
      \item \texttt{numero\_secuencia = i}
      \item \texttt{dato = random(1-1000)}
      \item \texttt{texto} = "Send[ID]-Msg[NUM]-[LETRA]-Dato:[VALOR]"
    \end{itemize}
    \item Enviar con \texttt{msgsnd()}
    \item Imprimir confirmación
  \end{enumerate}
  \item Enviar mensaje \texttt{TIPO\_FIN}
  \item Terminar
\end{enumerate}

\subsection{Implementación del Consumidor (receive.c)}

\textbf{Modos de operación:}
\begin{itemize}
  \item \texttt{normal}: 500 ms de procesamiento por mensaje (balanceado)
  \item \texttt{lento}: 2000 ms por mensaje (Análisis A - buffer lleno)
  \item \texttt{rapido}: 0 ms procesamiento (Análisis B - buffer vacío)
\end{itemize}

\textbf{Pseudocódigo:}
\begin{enumerate}
  \item Parsear argumentos: modo y cantidad de productores esperados
  \item Conectar a cola de mensajes
  \item \texttt{mensajes\_fin = 0}
  \item Mientras \texttt{mensajes\_fin < productores\_esperados}:
  \begin{enumerate}
    \item Recibir mensaje con \texttt{msgrcv(msqid, \&msg, size, 0, 0)}
    \item Si \texttt{msg.tipo == TIPO\_FIN}:
    \begin{itemize}
      \item Incrementar \texttt{mensajes\_fin}
      \item Continuar
    \end{itemize}
    \item Si \texttt{msg.tipo == TIPO\_DATO}:
    \begin{itemize}
      \item Simular procesamiento (\texttt{usleep(delay)})
      \item Imprimir mensaje recibido
      \item Incrementar contador
    \end{itemize}
  \end{enumerate}
  \item Mostrar estadísticas finales
  \item Eliminar cola con \texttt{msgctl(msqid, IPC\_RMID, NULL)}
\end{enumerate}
